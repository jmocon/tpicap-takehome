### 2026-09-19 — Docker path: SPA fallback + `/api` prefix, and real `.env` loading (devops-engineer)

Fixed the two structural Docker bugs from the audit above (findings at lines "frontend/Dockerfile ... no SPA fallback" and "nginx/default.conf:30 ... /positions collides"), plus the `cp .env.example .env` no-op. **Docker is still not installed here — none of this was executed.** Everything below is hand-traced against the configs and the code, and both npm builds/test suites were re-run (backend 80 tests, frontend build) to confirm nothing else broke.

- **SPA fallback** — new `frontend/nginx.conf` (`try_files $uri $uri/ /index.html`), copied over the stock `default.conf` in the frontend image. Stock `nginx:alpine` has no history-API fallback, so with `react-router-dom` routes at `/login`, `/positions`, `/symbols/:symbol`, every hard refresh / pasted deep link 404'd; only `/` worked. Also: `/assets/` gets `try_files $uri =404` (a missing hashed asset must stay a 404, not silently become index.html served as JavaScript) + immutable caching, and `location = /index.html` sets `no-cache` so a stale shell can't keep requesting a previous build's hashed assets. Confirmed against the real build output — Vite emits `dist/assets/index-<hash>.{js,css}` and references them with absolute `/assets/...` URLs, so deep links resolve assets correctly.
- **`/api` prefix** — `nginx/default.conf` now has a single `location /api/ { proxy_pass http://backend:4000/; }` in place of the four per-resource locations. The trailing slash on `proxy_pass` strips the prefix, so the backend keeps serving `/trades`, `/positions`, `/auth/login`, `/health` unchanged (`backend/src/app.ts` mount points untouched). This is the structural fix rather than a special case for `/positions`: the SPA now owns the entire root namespace and no future backend route can shadow a page. `/ws` deliberately stays outside `/api` — `WS_PATH` in `ws-server.ts` matches that exact pathname, and there's no SPA route to collide with. `docker-compose.yml`'s `VITE_API_BASE_URL` build arg becomes `http://localhost:8080/api`; `VITE_WS_URL` unchanged.
- **Non-Docker flow verified unaffected** — `http-client.ts` is `${BASE_URL}${path}` with every call site passing a leading-slash path, and `BASE_URL` falls back to `http://localhost:4000` when `VITE_API_BASE_URL` is unset, so the two-terminal dev flow needs no prefix and no `.env`. No trailing-slash/`//trades` hazard: the base never ends in `/`.
- **Request traces** (browser → nginx location → backend): `/positions` → `location /` → frontend nginx → no such file → `/index.html` → React Router renders the positions page. `/api/positions` → `location /api/` → backend `GET /positions`. `/api/auth/login` → backend `POST /auth/login` (public, before `authMiddleware`). `/api/health` → backend `GET /health`. `/ws?token=…` → `location /ws` (no rewrite, upgrade headers set via the `map $http_upgrade $connection_upgrade` block) → `WebSocketServer({ path: "/ws" })` matches.
- **`.env` is now actually loaded** — the audit was right: no `dotenv`, no `--env-file` anywhere, so `cp .env.example .env` did nothing. Chose to make the documented step real rather than delete it: backend `dev`/`start`/`db:migrate`/`db:seed`/`db:seed:mock` now pass Node 24's built-in `--env-file-if-exists=.env` (no dependency added). The `-if-exists` variant matters — plain `--env-file` exits with code 9 when the file is missing, which would break the "just run it" path, CI, and the Docker image. Verified empirically on Node 24.20.0: (a) `tsx` and `tsx watch` both forward the flag to node, (b) a missing file only logs "Continuing without it", (c) **real environment variables win over `.env` values**, which is what keeps Docker Compose's `environment:` block authoritative. Smoke-tested `npm start` on a scratch DB: boots, `/health` → 200, `/trades` without a token → 401, and `.env` values are genuinely read now. The backend Dockerfile's `CMD` is intentionally left as plain `node dist/index.js` — no `.env` ships in the image and compose passes everything explicitly.
- **Bonus fix spotted in passing** — `frontend/Dockerfile`'s `ARG VITE_WS_URL` default was `ws://localhost:4000` (no `/ws`), which would silently produce a client that can't connect on a plain `docker build` without build args. Now `ws://localhost:4000/ws`, matching `frontend/.env.example` and the in-code fallback in `trades-socket.ts`.
- **README** — "Running with Docker Compose" rewritten (it described the proxy as routing `/trades`, `/health`, `/ws`, stale on every count), architecture bullet updated, new "Configuration" section explaining the env-file semantics and the frontend's build-time `VITE_*` fallbacks, API table annotated with the `/api` prefix. The "never been run" caveat stays — and now names the two deep-link/live-update checks that would actually catch these bugs.

- `fifo-pnl.ts` — the core algorithm, `computeFifoPnl(trades: FifoTradeInput[]): { realizedPnl, openLots }`. A queue of open lots (signed by side); each trade drains opposite-side lots off the front FIFO, realizing P&L on the matched quantity (`BUY` lot closed by a `SELL`: `qty * (exitPrice - entryPrice)`; `SELL` lot closed by a `BUY`: `qty * (entryPrice - exitPrice)`), until either the trade or the queue is exhausted; any leftover quantity is pushed as a new lot. A long↔short flip falls out of this with no special-case branch — proven by a dedicated test showing the flip and a "FIFO not average-cost" proof test (BUY 10@100 + BUY 10@120, then SELL 15@150 realizes 650 via oldest-first matching, not the 600 an average-cost blend would give). Assumes pre-sorted chronological input; sorting is the repository's job.
- `positions.repository.ts` — `listActiveTradesChronological()`: `SELECT * FROM trades WHERE status='ACTIVE' ORDER BY trade_date ASC, created_at ASC, id ASC` (reuses `TradeRow`/`rowToTrade` from `trades/trades.types.ts`; `created_at`/`id` are tiebreakers since `trade_date` alone isn't guaranteed unique and `id` is a random UUID fragment, not chronological).
- `positions.service.ts` — groups active trades by symbol, runs `computeFifoPnl()` per symbol, derives `netQuantity`/`avgOpenPrice` from the remaining open lots (quantity-weighted average price), marks unrealized P&L to that symbol's last (active) trade price — documented in-code as a proxy since no real market-data feed exists — via `netQuantity * (lastPrice - avgOpenPrice)`, which works uniformly for both long and short positions without a sign special-case. No caching: recomputes fresh from the DB on every call, so a cancel is reflected on the very next request. ### 2026-09-18 — `GET /trades` symbol/trader filters: exact match → case-insensitive substring search
